# NIDOX INCY Routing

Автообновляемый профиль маршрутизации для [INCY](https://incy.cc/). Основной профиль повторяет политику **Bypass LAN**: локальная сеть идёт напрямую (`DIRECT`), а весь внешний трафик — через активный прокси (`PROXY`).

Это **не** конфигурация сервера и не подписка: здесь нет ключей, UUID, паролей или адресов VPN-серверов.

## Что делает основной профиль

| Трафик | Действие |
| --- | --- |
| Локальные, приватные и служебные сети | `DIRECT` |
| Внешние сайты и приложения, включая российские сервисы | `PROXY` |

Такой вариант полезен, когда сервисы работают надёжнее через один маршрут и не принимают смешение прямого и проксированного трафика. В профиле намеренно нет правила «все `.ru` / `.рф` — напрямую»: такой широкий обход легко отправляет через провайдера неучтённые ресурсы на общих доменах/CDN. Список `hxehex/russia-mobile-internet-whitelist` также намеренно **не** добавляется в `DirectSites`: его автор определяет его как список разрешённых SNI для ограниченной мобильной сети, а не как список сайтов для прямого доступа. Он скачивается лишь как диагностический артефакт `build/sni-allowlist.txt`.

Для тех, кому всё же нужен прежний split-routing, сборка выпускает отдельный `dist/ru-direct-profile.json`. Он не подключён к основной autorouting-ссылке: из-за проблем совместимости некоторых сервисов с прямым маршрутом включать его следует только после собственной проверки.

## Быстрый старт в INCY

**Учётная запись GitHub не нужна.** Репозиторий уже опубликован, поэтому достаточно открыть эту ссылку на iPhone/iPad, где установлен INCY:

[Добавить и активировать профиль в INCY](incy://autorouting/onadd/https://raw.githubusercontent.com/JonesPitkin/nidox-incy-routing/main/dist/profile.json)

Если ссылка открыта не на устройстве с INCY, скопируйте её и откройте там:

```text
incy://autorouting/onadd/https://raw.githubusercontent.com/JonesPitkin/nidox-incy-routing/main/dist/profile.json
```

INCY добавит и активирует профиль. Его URL будет проверяться каждые 30 минут; обновление произойдёт, когда прошёл заданный интервал (по умолчанию 24 часа). После обновления профиля выберите **Source Updates → Update now**, переподключите VPN и закройте/откройте браузер или приложение: так не останется старого DNS-кэша.

В настройках INCY сначала добавьте и проверьте рабочий сервер/подписку. Затем откройте ссылку выше. При необходимости вместо `onadd` используйте `add`, чтобы профиль только добавить, без активации.

### Если хотите вести свою копию

GitHub потребуется только в этом случае: сделайте fork или скопируйте проект в свой репозиторий, а затем подставьте в URL свой `<owner>/<repo>`. Это необязательно для обычного использования.

## Обновление списка

GitHub Actions запускается раз в сутки, а также вручную. Он:

1. скачивает исходные текстовые списки по HTTPS;
2. отбрасывает комментарии, дубликаты и некорректные значения;
3. не принимает чрезмерно широкие сети (шире `/12` для IPv4 и `/32` для IPv6);
4. генерирует основной `dist/profile.json`, необязательный `dist/ru-direct-profile.json`, манифест с SHA-256 и диагностический SNI-список;
5. выполняет тесты и коммитит **только изменившиеся** результаты в ваш репозиторий.

Внешние списки — данные сообщества, не гарантия доступности, полноты или безопасности. Перед эксплуатацией на конкретном операторе протестируйте несколько банков, Госуслуги, локальные устройства и нужные иностранные сервисы. При жёстком фильтре мобильной сети одного профиля маршрутизации недостаточно: способность установить VPN-соединение определяется отдельно оператором, IP сервера и TLS/SNI.

## Локальная сборка и проверка

Требуется Python 3.11+; внешние зависимости не нужны.

```bash
python3 scripts/build.py
python3 -m unittest discover -s tests -v
```

Чтобы собрать без сети из уже скачанных файлов, используйте `--offline`:

```bash
python3 scripts/build.py --offline
```

## Структура

```text
config/profile.template.json  Непеременные настройки INCY
scripts/build.py              Скачивание, валидация и генерация
dist/profile.json             Основной Bypass-LAN-профиль Autorouting
dist/ru-direct-profile.json  Необязательный профиль с российскими DIRECT-правилами
dist/manifest.json            Происхождение, хеши, статистика
build/sni-allowlist.txt       Диагностический источник SNI (не правило DIRECT)
.github/workflows/update.yml  Ежедневная безопасная пересборка
tests/                        Автотесты парсинга и профиля
```

## Источники и спецификация

- [Официальная документация INCY Autorouting](https://docs.incy.cc/autorouting/) — URL-профиль, deeplink и цикл обновления.
- [Официальная спецификация Routing](https://docs.incy.cc/en/routing/) — поля `DirectSites`, `DirectIp`, `GlobalProxy` и DNS.
- [112fm/OpenSmart-Russia](https://github.com/112fm/OpenSmart-Russia) — курируемые `direct-domains.txt` и `direct-cidrs.txt`.
- [hxehex/russia-mobile-internet-whitelist](https://github.com/hxehex/russia-mobile-internet-whitelist) — SNI/IP-наблюдения для условий ограниченного мобильного интернета; используется только для диагностики.

## Безопасность и откат

- Проверяйте изменения в автоматически созданных коммитах: у источников нет криптографического закрепления содержимого.
- Не добавляйте в правила адрес вашего прокси-сервера или его домен: это может создать маршрут в обход туннеля.
- Не помещайте секреты в `profile.json`, workflow, Issues или Actions logs.
- Чтобы отключить эффект профиля, выберите другой профиль либо удалите «NIDOX · Bypass LAN / proxy fallback» в INCY. Удаление репозитория не отменяет уже установленный профиль на устройстве.

Используйте в соответствии с применимым законодательством, политиками сети и условиями провайдера.
